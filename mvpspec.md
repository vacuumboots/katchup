# katchup MVP Spec

App name: katchup. Repo directory: `katchup`.

## Goal

A phone-first web app that serves one good conversation question at a time, for use with someone you already know well (starting with parents). The use case: you are sitting with a person, the conversation has stalled, you pull out your phone, and a question gets them telling stories.

The product test for this MVP: the builder still reaches for it on the third Sunday in a row.

## Non-goals (do not build)

- Accounts, login, sync, backend, database
- Analytics or tracking of any kind
- Answer logging, notes, audio recording
- Per-person profiles or adaptive decks
- Sharing, social features, monetization
- AI calls at runtime
- Offline mode. A network connection is assumed and required. No service worker, no cache-layer complexity.

These are v2 candidates. Leave clean seams for them but write no code for them.

## Users and context

- One user, on a phone, in person, mid-conversation.
- A connection is assumed. No offline requirement, no PWA install requirement.
- Must be usable one-handed in under 2 seconds from opening: open app, see a question.
- The other person may glance at the screen. No clutter, no jargon.

## Tech

- Static site. Vanilla HTML, CSS, JS. No framework, no build step required.
- `questions.json` fetched once at startup and held in memory for the session. Rely on normal HTTP caching for repeat visits. Do not fetch it again on card changes.
- State in `localStorage`.
- A minimal `manifest.webmanifest` (name, icons, theme colours) so "Add to Home Screen" produces a clean shortcut. No service worker, so this is a shortcut, not an installed app. Installability is not an acceptance criterion.
- Deployable to any static host (GitHub Pages, Netlify, or a plain nginx directory). Include a short README with deploy notes.
- No external network requests at runtime. No CDN fonts. Use the system font stack.

## Data model

`questions.json` is an array of objects:

```json
{
  "id": "q0001",
  "text": "What was the last concert you went to?",
  "era": "young-adult",
  "topic": "music",
  "weight": "light",
  "kind": "memory",
  "followups": [
    "Who did you go with?",
    "What was the best one you ever saw?"
  ]
}
```

Field rules:

- `id`: unique, stable, never reused. Format `q0001`.
- `text`: one sentence, ends with a question mark, under 120 characters where possible. Must not be answerable with yes or no.
- `era`: one of `childhood`, `teens`, `young-adult`, `career`, `family`, `now`.
- `topic`: one of `music`, `food`, `cars`, `work`, `school`, `places`, `home`, `firsts`, `people`, `money`, `hobbies`, `media`, `advice`.
- `weight`: `light`, `medium`, or `heavy`.
  - light: easy, concrete, low emotional cost. Fine to ask cold.
  - medium: requires some reflection or touches something personal.
  - heavy: about regret, loss, big decisions, or the relationship itself.
- `kind`: `memory` (asks about a specific past thing), `opinion`, or `hypothetical`.
- `followups`: 1 to 3 short prompts to use if the first answer starts a story. Required for every question. Each ends with a question mark.

## Question content

Seed `questions.json` with 300 questions. Write them directly; do not scrape or copy from other sites.

Distribution targets:

- Weight: 195 light (65%), 90 medium (30%), 15 heavy (5%). Heavy is the scarcest thing in the deck on purpose: it is hidden by default, so a large heavy pool is dead weight.
- Kind: at least 180 `memory` (60%). Concrete past specifics beat abstract opinions. The proven example: "What was the last concert you went to?" led to stories about the 1970s.
- Every era and topic value is represented by at least 10 questions.
- No near-duplicates: no two questions may share more than roughly 60 percent of their significant words, or open the same door in different words.

Quality rules for writing questions:

- Ask for a specific thing, not a summary of a life. "What was your first car?" beats "What was your childhood like?"
- No yes/no questions. Nothing that opens with "Do you", "Did you", "Have you", "Are you", "Is there", "Can you", "Would you".
- No questions that assume a spouse, children, religion, a particular country, or a particular income.
- No "greatest fear", "biggest regret", or therapy-style prompts in light or medium. Those belong in heavy only, and sparingly. With only 15 heavy questions, each one has to earn its slot.
- Avoid trivia that needs a right answer.
- Plain wording. No cutesy tone.

### Validator

`scripts/validate_questions.*` must check and report:

- unique ids, matching the `qNNNN` pattern
- valid enum values for `era`, `topic`, `weight`, `kind`
- `followups` present, 1 to 3 entries, each ending with `?`
- `text` ends with `?`, is not empty, and prints a warning above 120 characters
- `text` does not open with a yes/no construction (regex list above)
- no duplicate text (case and punctuation-insensitive)
- near-duplicate pairs flagged as warnings (token overlap above 60 percent)
- distribution printout for weight, kind, era, and topic, with a pass/fail line per target

It exits non-zero on errors, zero with warnings printed otherwise.

Passing the validator is necessary but not sufficient. It checks shape, not whether a question opens a door, so the validator also writes `review.html`: one page, all 300 questions, numbered, showing their tags, meant for a single human read-through with a highlighter. Reviewing that page is a required build step, not an optional nicety.

## Screens and behavior

Single screen with a drawer or sheet for filters.

### Main card

- Large question text, centered, readable at arm's length.
- Small tags under the question showing era and topic (muted). Do not show weight or kind on the card: the other person can see the screen.
- A "Follow-ups" button that reveals the followups for the current question, one tap, collapsible.
- Three actions at the bottom, thumb reachable:
  - **Asked it**: marks the question as used (never shown again) and loads the next one.
  - **Skip**: loads the next one. The skipped question re-enters the pool after 10 other cards, or sooner if the filtered pool runs dry.
  - **Never**: permanently removes the question (bad fit, awkward, wrong for this person).
- **Back**: reverses the last action, one level only. Un-asks, un-nevers, or un-skips, then returns the previous card. Undo history is in memory for the session and does not survive a reload. Back is the safety net for a mis-tap on a destructive button, so it must reverse the mark, not merely show the previous card.
- Swipe gestures as an optional enhancement: swipe left for Skip, swipe right for Asked it. Buttons must work without gestures, and gestures must never be the only path to any action.
- The current question id persists in state, so reloading the page returns to the same card rather than a random new one.

### Filters (bottom sheet)

- Weight: multi-select chips, default light + medium.
- Era: multi-select chips, default all.
- Topic: multi-select chips, default all.
- Kind: multi-select chips, default all.
- Show a live count of remaining questions matching the current filters.
- Persist filters in `localStorage`.

### Selection logic

- Pick randomly from questions that match filters and are not marked asked or never.
- Prefer questions not skipped this session. A skipped question becomes eligible again after 10 other cards have been shown, or immediately if no unseen eligible questions remain.
- When nothing remains, show an empty state: "You have asked everything that matches these filters." with a button to open filters and a button to reset history.

### Stats and reset (settings sheet)

- Total asked, total remaining overall.
- "Reset history" (clears asked and never) with a confirm step.
- "Export history" downloads the state as JSON, and "Import history" loads it back. This is the only backup path in v1.

## State shape (localStorage key: `katchup_state_v1`)

```json
{
  "version": 1,
  "asked": ["q0001"],
  "never": ["q0042"],
  "skippedThisSession": [],
  "filters": { "weight": ["light","medium"], "era": [], "topic": [], "kind": [] },
  "currentId": "q0001",
  "history": [{ "id": "q0001", "askedAt": "2026-10-18T15:04:00Z" }]
}
```

An empty filter array means "all". `version` plus a simple migration hook (`migrate(state)` returning the current shape) covers later schema changes. Store `askedAt` timestamps now, so v2 features like "what did we cover last Sunday" are possible without a data migration. Unknown or missing `currentId` falls back to a fresh random pick.

## Design

- Dark and light themes via `prefers-color-scheme`.
- One accent color. High contrast, at least 4.5:1 for body text.
- Question text 28px or larger; minimum 18px body text.
- Tap targets: the three action buttons at least 76px tall with generous width, because they are pressed one-handed while talking and a mis-tap costs a question permanently. Chips at least 48px. Nothing important in the top corners.
- No animations beyond a short fade between cards. Respect `prefers-reduced-motion`.
- No emoji, no mascots, no confetti.

## Layout and speed requirements (measurable)

Checked at a 375 by 667 viewport with the browser UI visible:

- The full question text is visible without scrolling at its normal size, for every question in the deck (no truncated or clipped cards).
- All three actions sit entirely inside the bottom quarter of the screen.
- No horizontal scrolling at any point.
- First visit reaches a visible question in under 2 seconds on a mid-range phone over mobile data. Repeat visits are effectively instant, which normal HTTP caching should deliver without extra machinery.

## Acceptance criteria

1. Loads and shows a question in under 2 seconds on a mid-range phone on first visit, and instantly on repeat visits.
2. Layout requirements above hold: question text fully visible without scrolling, actions in the bottom quarter, no horizontal scroll.
3. Asked and never questions do not reappear after a page reload, and the current card does.
4. Back reverses the last action: after Ask then Back, the question returns and is no longer in `asked`.
5. Filters change the pool immediately and the remaining count is accurate.
6. All 300 questions pass the validator and meet the distribution targets, and the full deck has been read once on `review.html`.
7. Export then import on a cleared browser restores state exactly.
8. After `questions.json` loads, no further network requests occur while changing cards.
9. No console errors. Every control is reachable by keyboard. Changing the card is announced to screen readers (`aria-live`), and Lighthouse accessibility runs with no major failures.

## Build order

1. Write the schema, the validator (including the `review.html` emitter), and the first 40 questions. Run the validator.
2. Build the card screen with selection logic: Asked, Skip, Never, Back, and the skip re-entry window.
3. Add `localStorage` state, `currentId` restore, and filters.
4. Add the manifest and icons as a home-screen shortcut. No service worker.
5. Fill out the remaining questions to 300 in batches of about 50, validating after each batch. Keep a running count against the 195/90/15 weight target so the last batch is not forced to absorb a correction.
6. Read `review.html` end to end and fix the questions that feel like filler.
7. Add settings, export, import, and reset.
8. Write the README with deploy steps and a note on how to add questions.

## Open decisions (default shown, change if you disagree)

- Name: katchup.
- Default filter weights: light + medium (heavy hidden until the user turns it on).
- Skip behavior: soft skip, re-enters after 10 cards.
- Hosting: static host of the builder's choice.
- Undo: last action only, session only.

## v2 ideas (explicitly out of scope now)

- One-line note per asked question, so the stories get saved.
- Per-person decks and history ("Dad", "Mom") so you never repeat across people.
- Era-aware prompts keyed to birth year (for example, music from when they were 17).
- Add your own questions.
- Printable card export.

## Revision notes

Changes from the first draft, and why:

- Removed the offline and PWA requirements, the service worker, and the airplane-mode acceptance criterion. A connection is assumed. This deletes a whole class of cache-staleness bugs for a product that would only have exercised them weekly.
- Heavy cut from 10 percent to 5 percent (30 questions to 15). Heavy is hidden by default, so most of that pool would never be seen.
- Back is defined as undo of the last action, not a viewer, so a mis-tap on Asked or Never is recoverable.
- Tap targets raised from 44px to 76px for the three actions, and the measurable one-handed layout requirements were added to acceptance.
- The skip promise was made concrete (re-enters after 10 cards) instead of "when the pool is exhausted", which could never happen in a 300-question deck.
- `currentId` added to state so a reload returns to the same card.
- Validator gained yes/no detection, near-duplicate warnings, and the `review.html` human review gate, because the validator can only prove shape and content is the actual product.
